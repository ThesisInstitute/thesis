# Thesis core: implementation plan

Status: proposed for Fable review before implementation.

This implements the from-scratch architecture discussed with Max on September 4, 2026, in `ThesisInstitute/thesis`. The user authorized writing this plan, obtaining Fable review through Subfleet, then building it. ## Outcome and scope

Deliver a working forecasting experiment system: a Python core, PostgreSQL persistence and jobs, content-addressed evidence artifacts, source capture, a deterministic baseline and a real subprocess forecaster interface, externally verified publication evidence, automatic resolution and scoring, read-only HTTP exports, and a thin Next.js browser view. A documented local command sequence must exercise the complete loop against a real local PostgreSQL instance; an offline replay must remain explicitly labeled as replay and cannot enter a prospective leaderboard.

The new core lives alongside the existing Brier package and publication workflows. Existing public records retain their bytes, identities and proof chains. The implementation includes an explicit read-only legacy import boundary, not a switch that rewrites historical records. The deliverable is a tested branch and reviewable change; production database provisioning, historical migration, and replacing current scheduled publishers are a later explicit release decision. This boundary prevents an unfinished deployment migration from becoming the definition of building the core.

The architectural review is at `/Users/maxghenis/architecture-reviews/thesis-20260904/review.md`. Its findings motivate this design: exports must retain recorded configuration hashes, forecaster identity must be frozen, partial successes must survive unrelated failures, and official-source collection must not depend on website builds.

## Architecture and ownership

One repository and one Python domain package, `thesis_core/`. Core logic imports neither Next.js modules nor the legacy script monolith. Versioned adapters may call existing verified custody/registration import interfaces at an explicit compatibility boundary. Do not copy arbitrary chunks of the resolver into a second monolith.

Shared primitives move in one direction: the canonical JSON implementation, RFC 3161 verification/trust-bundle implementation, and subprocess environment/redaction helpers become importable `thesis_core` modules; existing scripts keep compatible imports/re-exports and CLI wrappers. The original Python/TypeScript parity, credential-hygiene and trust-transition tests exercise the moved implementations. `publication.py` uses the very same pinned anchors, allowed signer identities, policy/imprint OIDs and time checks as the legacy verifier; it does not introduce another TSA trust policy. Preserve test monkeypatch/import behavior where wrappers expose legacy names. The pure compatibility modules must remain usable without importing optional HTTP/database dependencies. Existing scheduled workflows invoke both direct `python3 scripts/...` entry points (including `resolve_pending.py`, `verify_custody.py`, `run_thesis_batch.py` and the absolute-checkout `run_thesis_analyst.py` canary) and `uv run --locked --extra custody python scripts/verify_record_chain.py records`. Compatibility wrappers must bootstrap the checkout root when used directly, while installed imports resolve packaged resources. CI must exercise direct script imports/CLI help in a clean subprocess without PYTHONPATH or an editable installation, including an absolute script path from another working directory, and the locked custody verification entry point. Run these checks in a clean custody-only locked environment without the core extra, as well as the full development environment, so optional-dependency leaks cannot be hidden by installed packages. This verifies the actual invocation modes without changing publisher workflows.

Proposed modules:

- `contracts.py`, `canonical.py`, `schema.py`: strict immutable domain models, content identity, generated JSON Schema and TypeScript contracts.
- `store.py`, `migrations/`: PostgreSQL records, relational links, immutable scientific events, mutable operational jobs, transactional outbox, migrations and query methods.
- `artifacts.py`: atomic local content-addressed artifact storage with verification on read; a storage protocol permits remote object storage without changing domain code. Production S3 support can be a concrete optional adapter if it does not distract from the tested local backend.
- `evidence.py`, `adapters/`: archived source exchanges and pure parsers behind one capability registry; evidence bundle construction and vintage eligibility.
- `execution.py`, `worker.py`: durable attempts, deterministic retry policy, worker claims/leases and recovery, persistence baseline, explicit subprocess transport and sanitized activity capture.
- `publication.py`: sealed manifests, verified RFC 3161 timestamp receipts, publication state and retryable publication jobs.
- `scoring.py`, `evaluation.py`: exact versioned CDF scoring, typed exclusion reasons, cohort inclusion, matching baseline cutoffs, replay separation and training cutoffs.
- `legacy.py`: read-only import of registered contracts and verified sealed runs, preserving source hashes and original provenance. Legacy claimed time does not become new prospective proof.
- `api.py`, `cli.py`: local operational CLI and read-only HTTP interface. A new site route fetches this API and has no build-time database dependency.

Use PostgreSQL for the actual persistence and concurrency acceptance tests; do not substitute an in-memory or SQLite implementation and claim the database path works. Minimum supported major is PostgreSQL 14; the dedicated required CI job has a PostgreSQL 14 and 16 matrix, each exercising migrations, SKIP LOCKED claims, fencing, concurrency and recovery. Root verified `/opt/homebrew/bin/postgres`, `pg_ctl`, `initdb` and `psql` locally (`postgres --version` returned 14.22), so local tests can start a temporary isolated cluster on a private socket. Set `THESIS_CORE_REQUIRE_POSTGRES=1` in the dedicated CI job and the documented full acceptance command: missing/unreachable PostgreSQL is then a hard failure. Without that flag, database tests may skip only with an explicit actionable reason; they cannot be counted as accepted verification. Supply a documented helper command for an isolated temporary cluster. Keep current lockfile dependencies where usable and add only the core extras needed for validated models, PostgreSQL access and the HTTP API.

Ship `thesis_core` inside the existing distribution: extend setuptools package discovery to `brier*` and `thesis_core*`, package migration/schema/trust assets explicitly, add the `thesis-core` console script and a `core` optional extra, and regenerate `uv.lock`. Extend packaged-smoke coverage to the built wheel with the core extra, including import, CLI, schema and migration asset discovery outside the repository checkout. Existing `uv --locked --extra custody` commands must remain valid with the updated lockfile.

## Domain contracts

Every scientific object has a schema version and a full SHA-256 content identity over a defined canonical payload. Reuse the repository's tested canonical JSON semantics instead of inventing a third serializer. Canonical-byte/hash parity is tested across Python and TypeScript, including numeric and Unicode edge cases. Persist the canonical payload bytes as an artifact as well as queryable columns. IDs are verified on ingestion rather than trusting an ID supplied alongside different content.

1. **Source series:** adapter identity and version, official source bindings, exact measure/dimensions, unit and supported vintage policies. Use one registry to generate cross-language declarations.
2. **Target version:** stable logical target ID plus immutable contract ID; measurement period distinct from release date/window; unit, source-series binding, exact resolution policy and rule, expected release evidence (an archived official artifact hash, its source URL/documented timezone and a versioned parsing rule), deadline and creation/registration metadata. Contract changes produce new versions. Unsupported first-print claims refuse.
3. **Forecaster version:** provider/model request, actual model identity when supplied by the provider, inference settings, agent and harness code versions, prompt-template/system/briefing/tool-policy hashes, aggregation procedure and retry policy. Preserve the full assembled prompt artifact separately. Requested and observed model identity must never be conflated.
4. **Experiment/evaluation task:** the dependency graph is explicitly acyclic. EvaluationTask references target version, forecaster version and sealed evidence bundle, and contains information cutoff, submission deadline, maximum attempts and deterministic submission-selection rule; it does not reference an experiment/cohort. Experiment is the authoritative preregistration record and references the concrete immutable task IDs, target/forecaster IDs and normalization record IDs. Every member task must match the experiment and its paired baseline constraints. In the initial protocol a task ID belongs to at most one experiment; registration and a database uniqueness constraint reject shared task membership. Test reuse across two independently witnessed experiments. Registration also rejects duplicate (target version, forecaster version) member pairs. Each target has exactly one task per declared forecaster and one matching baseline task, so cohort weights are unambiguous; test a duplicated pair. Thus an attempt has exactly one cohort proof dependency, selected by its task ownership. Normalizations reference target/series/vintage IDs and their cutoff, never task or experiment IDs. Runs reference attempts, attempts reference tasks; publication manifests reference experiment and optional run; proofs reference manifests. Thus all member contracts and concrete scale records exist before the experiment can be hashed/witnessed, with no task-to-cohort back edge. The initial protocol requires one shared information cutoff for every member task. Registration rejects differing member cutoffs in both modes. Prospective registration additionally rejects a bundle frozen after that cutoff or its target first-print boundary; all prospective member bundles must be frozen before the independent cohort witness. Explicit historical replay may assemble bundles later under the replay evidence rules and can run offline without a trusted receipt; it receives no prospective eligibility. A future rolling experiment needs a new preregistration/bundle-binding protocol; it is not represented by overstating a later cutoff. Test a two-member experiment with different cutoffs and a late-frozen bundle. Only `first_valid` submission selection is initially supported, where first means the smallest durable attempt sequence number assigned atomically at `attempt_started`, never completion or acceptance order; a lower unresolved attempt prevents selection of a higher attempt until reconciled. Test reversed completion order. Unsupported selection rules refuse. Unsupported aggregation modes refuse rather than quietly behaving like first-valid. A baseline uses the same official evidence bundle and cutoff. An explicit `replay` mode cannot acquire prospective eligibility.
5. **Observation vintage:** series, measurement period, value/unit, source publication time when authenticated, retrieval and acceptance times, raw source artifact, parser version, vintage policy and publication proof status. Unknown publication times stay unknown. Revised values are new vintages.
6. **Attempt and forecast run:** an attempt exists durably before model invocation. Record execution start, completion/failure/unknown outcome, sanitized command/input/output artifacts, model response metadata, validated original 201-point CDF, and immutable manifest. Each transition is an event; job status is an operational projection. A completed attempt is never silently replaced.
7. **Publication proof, resolution and score:** exact subject hash, verified witness time/trust configuration; target-version/observation link with resolution validation; run/resolution/scoring-code IDs with raw CRPS and diagnostics. Scores are reproducible derived records, and a new scoring version yields a new record. Nullable reward and explicit exclusion status preserve incomplete cases.

Strict models reject non-finite values, naive timestamps, invalid units/bindings, unknown enum values, malformed content hashes and invalid distributions. The existing `numeric_cdf_v1` 201-point contract remains unchanged. Import materialized CDF bytes; never rebuild a legacy forecast from its interval summary.

## Evidence and source adapters

Separate fetch, parse and accept. Archive a successful HTTP response before parsing so a later parser fault cannot destroy first-print evidence. Handle each source/job independently. Missing sources are deferred or failed with typed status, never fabricated observations. Store response body, source URL, collector retrieval time and relevant response metadata. Adapters declare credential-bearing URL parameters and headers; redact those fields and apply the shared credential scrubber to URL/metadata before canonicalization, hashing or persistence. Tests assert query keys (including UserID/API-key variants) and authorization headers never appear in persisted/exported exchange metadata. The BEA iTable path does not require an API key, but this protection applies to any transport. Collector-local times are descriptive only: a capture-derived availability upper bound must use database time sampled after successful commit of the archived response record (a durable commit acknowledgement), or a verified witness upper bound. Database-generated acceptance acknowledgements are not caller-overridable. A crash after archive commit but before acknowledgement leaves an unknown capture upper bound; the record is excluded from prospective bundles, normalization and as-of exports until repair writes a fresh later database acknowledgement. Repair never backdates. Acknowledgement existence is mandatory even when the payload has authenticated publication metadata; publication evidence never waives a missing acknowledgement. Test this two-transaction crash boundary both with and without authenticated publication metadata. Test a collector claiming pre-cutoff retrieval when its archive commits after the cutoff; it cannot enter a prospective bundle.

Start with three recurring numeric families with existing official fixtures: ABS Labour Force unemployment rate (`tests/fixtures/international/abs_lfs_unemployment_rate.json`), Statistics Canada CPI (`tests/fixtures/international/statcan_cpi_v41690973.json`), and BEA private nonresidential fixed investment (`tests/fixtures/ingestion_wave1/bea/gdp-advance-2026-q2.html` plus `nipa-table-5-3-5-2026-q2.json`). Extract the shared `abs_series_from_payload`, `normalize_sdmx_period`, `statcan_series_from_payload`, `intl_transformed_value`, `bea_itable_value` and required pure release/binding checks from the legacy resolver into the core; preserve legacy calls through imports. The relevant declarative specs, exact dimension selectors, verified anchors, transforms, units, rounding and valid ranges remain part of their versioned adapter contract. Existing international admission tests in `tests/test_resolve_pending.py` and BEA tests must continue exercising the shared implementations through their original imports. Each adapter has historical fixture tests, unit/series/period checks, and a live-fetch entry point. A current-estimate API response is not automatically a first print: mark it as current/unverified or fixed-vintage unless the registered policy and archived evidence prove first-print eligibility. The initial prospective benchmark forecasts a period before its first official print, even if its resolution policy selects a later fixed vintage. Registration of a prospective fixed-vintage contract requires archived official evidence identifying the first print for that same series and measurement period; a revision date or capture window alone is refused. Its outcome boundary is the earliest authenticated publication of any value for the period, including that first-print release, never moved later by the resolving revision. Dedicated tests exclude a forecast witnessed between the first print and the later resolving vintage. A future revision-forecasting experiment would be a separately versioned protocol, not silently mixed into this benchmark. The adapter registry declares capabilities so the resolver cannot silently downgrade a first-print target.

Evidence bundles contain exact observation IDs and artifact hashes. Construction is deterministic and uses availability intervals. Prospective evidence requires the authoritative archive/acceptance commit acknowledgement at or before the task cutoff, which establishes an upper availability bound even when payload publication metadata is absent; collector-local retrieval timestamps never prove this condition. Replay may permit later local acceptance only if established_upper, defined once in the timing section below, is at or before the historical cutoff; an unknown upper bound excludes the vintage. Neither mode may use the lower publication bound to prove evidence was already available. Test late acceptance allowed only in replay, date-only publication with cutoff inside the day, and DST ambiguity with cutoff between the two possible instants. Tests include late capture of an earlier publication, revisions, wrong series, future information, unit mismatch and incomplete proof. For this evidence-bundle-only protocol, exports, leaderboard rows and public manifests report both the declared information/scheduling cutoff and the effective bundle freeze boundary (the bundle post-commit acknowledgement, also labeled evidence_frozen_at). A valid prospective experiment requires this freeze bound strictly before the independent cohort witness and declared cutoff. Historical replay may assemble the bundle after its historical cutoff; it must show that later freeze time and the replay label rather than pretend it was executed historically. Export/manifest tests assert both fields, exact equality of the freeze bound to the bundle acknowledgement, and effective < declared for prospective experiments. Replay tests permit later assembly only with the historical evidence checks. A site Vitest verifies distinct labels and the replay disclosure. The first protocol is evidence-bundle-only; open-web research is an explicit future protocol rather than an unenforced claim about what a subprocess could have accessed.

## Execution and recovery

Use PostgreSQL `FOR UPDATE SKIP LOCKED` for claims, short transactions, unique job/idempotency keys, lease ownership tokens and explicit transitions. PostgreSQL clock time is authoritative for lease acquisition/expiry, heartbeat, attempt_started, deadline checks and every ownership-conditioned write; worker-local clocks are never authoritative. Check token, generation and unexpired database deadline in the same conditional statement/locked transaction as the write. Test a deliberately skewed worker clock. An outbox entry is committed in the same transaction as the scientific record that requires follow-up work. At-least-once job delivery must not create duplicate scientific objects or eligible submissions.

A worker commits `attempt_started` before invoking any subprocess. A normal failure persists stderr/status and may schedule the next allowed attempt. The task maximum is the sole bound on creating durable attempts, and every such creation goes through attempt_started. The forecaster retry-policy field describes the committed transport policy and affects identity; it cannot independently create additional durable attempts. Any provider/HTTP retry occurs inside the same attempt and is recorded where observable. Generic subprocesses must disclose when their provider retry behavior is unobservable; do not assert a complete internal retry count. A lost worker/lease after invocation marks the outcome unknown and blocks automatic model re-execution until explicit reconciliation; do not turn a crash into unrecorded retries. Reconciliation is mechanical and terminal. Only a validated sealed manifest committed in PostgreSQL under the attempt's valid lease/fencing token before lease loss counts as a persisted result; a later or orphaned artifact-store upload is ignored and flagged. Such a committed result resolves the attempt to valid; absent it, reconciliation records failure for selection while preserving the unknown execution history. The caller cannot choose the status or supply a replacement forecast. Exactly one reconciliation event per attempt is permitted, and repeated requests refuse. An unreconciled attempt yields `unresolved_attempt`. Tests cover stale artifact uploads after lease loss and a second reconciliation request. Record an immutable reconciliation event with actor, reason, evidence hashes and database time. Selection dependent on a reconciliation at or after the outcome-availability boundary (or with unknown ordering) is excluded from prospective ranking as `late_attempt_reconciliation`. Test two witnessed attempts and a post-boundary reconciliation; operators cannot choose a favorable submission after seeing outcomes. Stale workers cannot finalize a result after losing ownership. A persisted result whose publication job fails remains available for publication retry without rerunning the model.

The subprocess backend executes an argv vector, not an interpolated shell command, in a dedicated working directory populated with declared evidence and prompt files. Preserve existing allowlisted environment and pre-seal redaction protections. Treat filesystem/network isolation as an explicit runtime capability: do not claim a generic local subprocess proves absence of outside access. Label operator-run executions accordingly, and keep stricter publication eligibility dependent on the registered execution/proof policy. A bounded real model smoke run may validate transport without claiming historical forecast skill.

## Publication and public verification

Upload immutable artifacts first, verify their bytes, then commit the manifest plus publication job transactionally. The scientific database is operational authority, not proof against a database administrator. Public bundles commit targets, forecaster configuration, evidence, attempts, forecast, the full preregistered experiment/cohort and frozen comparison-set definition (including normalization identity), and relevant code identity. The cohort is itself content-addressed and, for prospective execution, MUST be independently witnessed before dispatch. Offline replay may omit this proof and remains explicitly ineligible for prospective claims. Each prospective attempt_started record and later run manifest also commits the exact independent cohort proof ID and receipt/token hash, verified before dispatch. The unpredictable receipt is thus part of the sealed execution input and public run commitment; a cohort definition hash alone is insufficient. The worker refuses dispatch without this proof dependency, and public verification checks the included receipt bytes and membership. This proves receipt inclusion order without comparing database and TSA clocks. A later run witness cannot substitute for the earlier independent cohort witness. Test a cohort witnessed after a member run was sealed/witnessed: the missing or mismatched prior receipt commitment excludes that run. Prospective ranking requires a valid cohort witness strictly before the earliest member information cutoff and submission deadline, as well as the earliest member outcome-availability boundary; a database creation timestamp is insufficient. A cohort defined after any member outcome boundary is excluded from prospective ranking even if every run was individually witnessed earlier. Test post-outcome cohort definition and a cohort witnessed after a member submission deadline but before all outcomes. No operator-selected cohort deadline can relax these bounds.

Use an actual RFC 3161 verification path with pinned trust roots and archived request/response tokens. A supplied timestamp string or boolean `verified` is never sufficient. Keep raw receipt verification distinct from the run's eligibility checks. Local test trust roots are confined to explicitly test/replay configuration and never make a prospective public record eligible. Pending or failed witness requests preserve the sealed run; publication retries target the same subject hash. No private producer key is required to test the local implementation, and no new external keychain credentials are read without the existing agent-secrets workflow.

For a prospective score, require a valid target/forecaster/task, accepted execution policy, complete verified artifacts, the selected submission, a valid witness before the submission boundary and the outcome-availability lower boundary (the earliest official print for the same series/period), and a mechanically valid resolution. Return precise exclusion reasons otherwise. Importing existing Thesis proofs preserves their original trust class; it cannot upgrade claimed-time records to witnessed records.

Define availability as an interval with independently established lower and upper bounds. Cutoff inclusivity is explicit: data/evidence and as-of filters admit known upper bounds and required acknowledgements <= their cutoff; scientific ordering of cohort receipt, dispatch, submission witness and outcome boundary is strict (<). A valid prospective bundle freeze is strictly before its declared cutoff because the mandatory cohort witness lies between them. Tests exercise equality for inclusive data/as-of filters and reject equality for strict witness ordering. Authenticated publication metadata is an explicit publication field inside an archived official response from the registered host, extracted by a versioned adapter with documented semantics; HTTP Date/Last-Modified and CDN regeneration metadata never establish first publication. Partial values lacking a time or offset span all instants consistent with that value in the source's documented IANA timezone: date-only spans the local day, DST ambiguity spans both possible instants, nonexistent local time or unknown zone yields no publication interval. For prospective outcome ordering use the earliest lower bound among all established official evidence for any print of the same series/period, including the first-print calendar artifact and resolving-vintage metadata. There is no preferred timestamp that overrides an earlier official boundary. Operator-selected windows, retrieval, acceptance and witness timestamps cannot establish this lower boundary. Unknown lower boundary excludes prospective scores as `outcome_availability_unknown`.

Define one established upper availability function for all consumers: the minimum of every valid known upper bound for the exact record/vintage — authoritative post-commit acknowledgement, authenticated official publication upper bound, and verified witness upper bound. A bound's absence does not contribute to the minimum; no known bound means unknown. A completed capture can tighten a broad date-only or DST-ambiguous publication interval, because the exact value demonstrably existed by capture acknowledgement. This never changes the separate outcome lower boundary. Contradictory lower/upper evidence is refused rather than silently relaxing the outcome rule.

Acknowledgement existence remains mandatory for every locally used record. Prospective evidence/normalization requires both acknowledgement <= cutoff and established_upper <= cutoff. Replay evidence/normalization may use later-acknowledged records when established_upper <= historical cutoff. As-of export requires every record and dependency to satisfy acknowledgement <= export cutoff AND established_upper <= export cutoff. The second check uses the minimum defined above, not an additional requirement that every individual candidate upper bound precede the cutoff. Publication metadata or a witness never waives the mandatory acknowledgement. Reparse official bounds through the registered adapter; collector clocks and free-text dates are not candidate bounds. Vintage-policy validation remains separate.

Pin expected partial-time results: for date-only publication with a noon acknowledgement and 13:00 cutoff, prospective evidence, replay evidence and as-of export all admit the acknowledged record; its upper bound is noon, not day end. If acknowledgement occurs after the cutoff and the only earlier metadata is date-only spanning that cutoff, all three exclude it. For a DST-ambiguous local publication, a cutoff between the two possible instants excludes later-acknowledged replay evidence; an acknowledgement at or before that cutoff tightens the upper bound and permits the record in all three consumers. Missing acknowledgement excludes every case. Tests cover these expected outcomes explicitly.

For witness ordering use the token's upper time bound: genTime plus signed RFC 3161 accuracy (seconds/millis/micros); absent accuracy requires a pinned TSA policy bound or yields unknown ordering. This upper bound must be strictly before the submission deadline and outcome lower boundary. Tests cover late capture of an old public result, unsupported operator windows, Last-Modified after an earlier official calendar release, date-only and DST-ambiguous values on both outcome and evidence/export paths, witness accuracy overlap, and release timing with no archived official artifact.

## Scoring, evaluation and consumers

Port the existing exact piecewise-linear CDF CRPS integral into the standalone core, with analytic golden tests and canonical-byte/hash parity against the existing TypeScript scorer. Preserve its output contract: 12 significant digits for CRPS and PIT, signed-zero normalization, and the existing knot-coalescing behavior for legacy distributions. Strict native distribution validation remains separate from the lower-level legacy-compatible scorer. Preserve the 201-point distribution verbatim. Keep raw CRPS available; normalized metrics require a frozen scale derived only from observation vintages admitted under the declared prospective/replay evidence rules, with established upper availability bounds at or before the task cutoff and, for prospective mode, strictly before the cohort witness, persisted as a content-addressed normalization record with the exact vintage IDs, cutoff, calculation version and scale, referenced by the experiment. Here normalization identity means the concrete scale-record content ID, not just a calculation-version label; prospective publication verifies its vintage upper bounds precede the cohort witness. A later revision of pre-cutoff history cannot change that record or normalized reward; test it explicitly. A scale is unavailable if non-positive, non-finite, or numerically degenerate under its versioned rule (initial floor: 1e-12 times max(1, maximum absolute historical value)). Such scales produce null normalized reward, missing paired coverage and no rank; tests include constant and near-constant history. If the scale is unavailable, normalized reward is null. Judges remain diagnostics outside reward.

Rank by a declared experiment/cohort and immutable forecaster ID, using an arithmetic mean of normalized proper scores on the frozen comparison set. Cross-series ranks require a valid frozen normalization record for every member; null normalized reward counts as missing coverage and forbids rank. Raw CRPS averages may be reported only within one source series and unit, never pooled across units. Test a comparison cohort with one missing normalization record. The initial ranking policy requires complete eligible paired coverage of that set; incomplete systems have descriptive statistics and coverage but no rank, avoiding an implicit favorable treatment of missing results. Compare baseline and model on the same target version, evidence cutoff and cohort; show coverage, failed/unknown attempts, latency and cost where recorded. Failed runs remain in the cohort denominator. Do not let favorable target selection or repeated updates silently redefine the evaluated population. Training exports require an explicit as-of cutoff. Every exported record and its transitive dependencies must have an authoritative database commit acknowledgement at or before that cutoff AND have established_upper at or before it, using the single minimum-of-established-bounds definition above. This is a conjunction: publication metadata never substitutes for a missing or late acknowledgement. Apply it to evidence, registrations, forecasts, receipts, reconciliations, resolutions and scores. Unknown/later records are excluded. Calendar split labels alone do not establish availability. Tests include an outcome publication exactly at the cutoff (inclusive), a missing acknowledgement despite known publication, a later acknowledgement, and a forecast sealed after the export cutoff even when its outcome was already available.

The API exposes health, experiments/tasks, runs with artifact/proof references, pending targets, observations, resolutions, reward rows and leaderboard summaries. It is read-only in this release; local CLI/worker code owns mutations. The website's new `/core` experiment view uses a read-only server proxy configured with `THESIS_CORE_API_URL`, declared `force-dynamic` in the Node runtime. The proxy uses an explicit allowlist of endpoint paths, rejects traversal/absolute URLs and unapproved query parameters, forwards no browser credentials/headers, and enforces a 5-second upstream timeout across fetch and body consumption and 2-MiB response cap enforced on bytes actually read from the stream. Abort immediately on overflow; Content-Length is only an optional early rejection and never the sole bound. The oversized-body test uses chunked data without Content-Length and an understated-header case. Use manual/error redirect handling: no upstream redirect is followed. Parse the media type case-insensitively and ignore parameters, accepting `application/json` including `application/json; charset=utf-8`, validate JSON, and return a fixed JSON content type; other upstream content types and redirects produce bounded JSON errors. The browser cannot supply arbitrary upstream destinations. It handles unconfigured API, loading, unavailable service, empty results and populated results. The site must build with the API URL unset and without a database or live source call from this new view. Vitest must cover unconfigured, timeout, upstream non-2xx, oversized response, rejected paths, redirects, JSON with charset parameters and non-JSON upstream bodies.

Avoid opportunistic rewrites of existing publication workflows in this architecture branch; their identified recovery bugs can be fixed separately or only through a narrowly tested shared primitive if required by the new core. The new core must not depend on those workflow gaps for its own publication semantics.

## Acceptance criteria

1. An isolated real PostgreSQL database initializes/migrates idempotently; immutable scientific records reject mutation; the same content inserts idempotently and different content cannot reuse an ID.
2. The complete register → capture/archive → freeze evidence → schedule → attempt → seal → witness → resolve → score → HTTP/browser export path works locally. Offline historical replay and prospective eligibility remain visibly distinct.
3. Two concurrent workers cannot execute the same attempt; lease loss cannot admit a stale finalization. A simulated crash after dispatch yields unknown outcome with no automatic replay; duplicate job delivery does not duplicate a run or score.
4. One failing adapter does not discard a successful capture from another. Source bytes remain available even when parsing or publication fails.
5. Tampered/missing artifacts and untrusted, invalid, late or mismatched witness receipts cannot produce a prospective score. Witness retry publishes the original sealed run without a second model invocation.
6. A changed target contract, model/protocol/briefing/harness setting creates a distinct immutable identity. Exported hashes equal recorded hashes; measurement period, release time and acceptance time remain distinct.
7. Scoring passes analytic and TypeScript parity cases; post-cutoff revisions cannot affect an earlier evidence bundle; comparisons require matching cohorts/cutoffs; training exports enforce outcome availability.
8. At least three official-source family adapters replay real fixtures, refuse wrong identities, and expose live capture commands. A real model transport smoke is recorded honestly without counting a historical replay as a prospective result.
9. Existing relevant Python/site tests, core PostgreSQL tests, type generation drift checks, site typecheck/build and affected browser flow pass. If live sources or a model account are unavailable, report the exact external limitation rather than weakening validation or substituting invented data.
10. Fable reviews this plan through a durable Subfleet gate. Resolve actionable findings and repeat the gate with exact new hashes. After implementation, obtain an independent code review, fix actionable findings, rerun relevant checks and deliver the branch with reproducible run instructions and explicit deployment status.
